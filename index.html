Plain English → working tool

Tool Studio build the analysis you actually need

Describe the test in a sentence — “join two payment exports on payment_id and flag any difference over 100” — and AuditLens writes a tool for it. One AI call builds it. Running it costs nothing, because it runs on your machine against your files. The data never goes to the model.

  • A methodology sheet, drafted from the code. Purpose, population, logic, exception definition and limitations — in review language, not source. The code becomes the appendix.
  • Review and sign-off bound to the exact version. A sign-off is a signed event against that specific code. Change the tool and the sign-off does not carry over.
  • Keep the good ones. Save a tool to your library, reuse it in any engagement, or share it with the team. Blueprints ship for IT general controls, journal entries, fraud & forensics, security operations and sampling.

Agent-assisted fieldwork

Frameworks & agent runs the agent works, you judge

Implement a framework pack — Treasury & Cash, ITGC, and others — and each control becomes a real test in your engagement. Bind the automatable ones to data and let the agent run the fieldwork steps end to end. It checks every item and brings each exception back to you for disposition.

Your judgment

The agent logs every exception at the lowest severity — it never rates severity, and it never decides risk. Rating and disposition stay yours, in the tracker. The run pauses until you acknowledge or stop it.

  • A control board you can read at a glance. Every control shows its state: exceptions awaiting judgment, or no automated test yet.
  • Remote evidence, read-only. Point the chase agent at an MCP server and it proposes documents matching your open PBC requests. Every fetch is approved here first; nothing is ever written back.
  • Drive it from outside, optionally. Let Claude Desktop or another agent operate AuditLens over localhost. External agents can read state and start work — every judgment still pauses here, for you. Off by default.

Questions

Frequently asked

If it tests 100 % of the population, what happened to sampling?
Population testing is the default because it is strictly better evidence when you can get the full listing: no sample to defend and no extrapolation to argue about in review. Deterministic rules decide most rows, AI drafts a call only on the ambiguous residue, and those rows stay flagged for your confirmation. Sampling still has its place where a full population genuinely is not obtainable, and the methodology blueprints in Tool Studio cover sampling approaches.
Do I have to trust AI-generated code in my workpapers?
No — you review it in review language, not source. Every tool AuditLens builds comes with a methodology sheet drafted from the code: purpose, population, step-by-step logic, the exception definition and the tool's limitations. That sheet is what a reviewer reads and signs; the code is the appendix. You can edit the sheet until it says exactly what you would defend, and re-draft it from the code at any time. Approving a tool records a sign-off bound to that exact code version — change the code and the sign-off does not carry over.
Does the agent decide whether something is a finding?
It does not. The agent performs the fieldwork steps and logs every exception it hits at the lowest severity — it never rates severity and it never decides risk. The run then pauses and hands the exceptions to you: acknowledge and let it continue drafting, or stop and investigate first. Rating and disposition happen in the exception tracker, by you.
Is my client data secure?
There is no AuditLens server in the path. The engagement lives in a folder on your machine, and AI requests go from your machine directly to your provider's enterprise API on your own key, which you can revoke at any time. Tools that Tool Studio builds run locally against your files — the data itself is never sent to a model, only the description you wrote. Remote MCP evidence sources are read-only and every fetch is approved by you first.
What does the AI actually cost to run?
Very little, because most of the work is not AI. The full ITGC engagement recorded on this page — eight pieces of evidence captured, analysed, drafted into workpapers and exported — cost $0.22 in total. Building a tool in Tool Studio is a single AI call; every subsequent run of that tool is free because it executes on your machine. Your current provider and running spend are always visible in the title bar.
What does my team get at the end of the engagement?
Ordinary files. A Risk-Control Matrix as real Excel, workpapers as real Word and Excel documents, exceptions as CSV, and a standalone audit file — one ZIP containing the evidence, narratives, findings, sign-offs and hash chains behind a browser-readable index. That ZIP needs no AuditLens and no licence to open, so your work outlives your subscription and survives any archive review.
Can I roll last year's workpaper forward?
Yes, and without AI touching it. Roll forward copies last period's .docx to a new file, applies each period pair as a tracked change, and adds a re-perform banner. Separately, AI pre-review can pass over a workpaper and raise unsupported conclusions, vague quantities and missing evidence references as Word comments on the exact sentences — comments you accept or reject in Word. Neither operation ever overwrites your text.
Where do populations come from?
Evidence Connectors pull them from SAP, Dynamics, Oracle, NetSuite or any REST endpoint, and you can always drop in a CSV or XLSX extract instead. You can also point the chase agent at an MCP server exposing search and fetch tools, and it will propose documents matching your open PBC requests for your approval — read-only, always.
Which AI providers and operating systems are supported?
AuditLens runs on Windows 10 and 11 (64-bit). It works with OpenAI, Anthropic Claude and Google Gemini on your own API key, switchable per task — or you can let AuditLens pick the cheapest model that will do the job. Mac and Linux builds may follow.
